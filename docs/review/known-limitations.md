## Haptics: delivered behaviour and D1 limit

At the **haptics** reference, an in-app hardware request captures the current visible activity host collection before save/service suspension. It emits one light `CLOCK_TICK` when the command owner accepts that request, and `CONFIRM` only for the **same request's returned BedJet-confirmed outcome**. Merely submitting or queuing the request does not tick. REFUSED, FAILED, UNKNOWN and unconfirmed ACCEPTED outcomes never produce the confirmation pattern; a refusal before admission produces no tick. Local settings/tracking actions have no hardware feedback.
