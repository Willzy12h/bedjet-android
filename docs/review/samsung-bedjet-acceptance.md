# Samsung + BedJet 3: supervised acceptance

Prepared 22 October 2026 and updated 23 October against the completion candidate, `docs/HANDOVER.md`, the hardening plan and `docs/review/register.md`; platform qualifications follow `platform-preflight.md`. Cases A08–A12 and N09–N13 were added on 24 October from the production code listed below, including the imported-original restore guard in this candidate. **No hardware has been tested. Every result below remains NOT RUN.** This is an executable acceptance specification for **BedJet 3 only**; mark an absent or unusable feature BLOCKED and identify its build/issue.

## Evidence and decision rules

**Historical completion-build evidence (23 October; not the fresh gate for this branch):** 148 core tests and 238 of 244 app tests passed; six app capture tests skipped; zero failures; debug assembled; lint zero errors, 22 warnings and one hint. An unsigned shrunk release build passed at 4,217,595 bytes. The shrunk test-signed APK is `outputs/nocturne-0.2.0-hardening-test.1.apk`: version `0.2.0-hardening-test.1` / code `2`, 4,229,883 bytes, APK SHA-256 `1b7ac2f81971b4ef83cb5392bd207d1f0f4859f876de79dd4f7c185921d3110d`, throwaway RSA 3072 certificate SHA-256 `8eba05db1a803aeb9b4b00ced5bae9bc56a1553d07c77d4216cafeddb452df67`; APK Signature Scheme v2 verified with `apksigner`. Fixed-clock Robolectric before/after captures are rendered app evidence. Fake transport, JVM/Robolectric tests and rendered screenshots cannot establish real BLE behaviour, Samsung background delivery, TalkBack usability, Lull interoperability or upgrade installation. These counts describe the recorded source gate and must not be transferred to a changed candidate. Use [nocturne-completion.md](nocturne-completion.md) for the fresh gate and fill in the actual artefact identity below before physical acceptance.

Candidate-specific release limits: IR-24 was rejected as a proven foreground-service timeout, while framework/Samsung timing is **NOT RUN**; IR-29 directory durability is best effort and needs phone/power-loss evidence; IR-31 legacy v1 `[]` cannot prove an originally empty slot. An upgraded real installation must have a supervised inventory and read-back restoration of the original slots before acceptance. Older literal UI strings have not all been moved to resources; verify UK English and accessibility on the phone.

Use PASS / FAIL / BLOCKED / NOT RUN. For every row, append tester, date/time with zone, observations and evidence filename/issue. A multi-part row passes only when every applicable part passes; record individual sub-results otherwise. Unsupported optional capabilities require a recorded BLOCKED limitation, never an assumed pass. Record requested, submitted and confirmed times separately; elapsed time alone is not proof of a device change. The BedJet display/physical remote and actual airflow corroborate fresh app status; they do not establish calibrated temperature accuracy.

For A08–A12 and N09–N13, retain the selected device/session identity, raw status fields and relevant command/read-back trace alongside app/History screenshots. Measure short intervals with a monotonic trace or independent stopwatch, and record wall time and UTC offset separately. A trace used to claim Start ordering must distinguish command submission, the Android write-completion callback and status arrival; an over-the-air acknowledgement alone does not establish callback order. If a required timing or status cannot be observed on the recorded phone/firmware, mark that subcase BLOCKED after attempting it and say what evidence is missing. Fake packets and deterministic tests remain separate evidence.

**Release acceptance remains NOT RUN.** No guarantee of waking, alarm delivery or exact scheduler timing is made. Use an independent, verified wake alarm throughout. Delayed best-effort work is acceptable only when described truthfully and safely expired; a false confirmed result, unexpected start, wrong-device write, lost original slot or post-boundary rewrite fails acceptance.

## Stop and recover — applies to every test

Stop immediately for unexpected heat/mode, uncontrolled repeated writes, wrong target, lost slot original, or an unresponsive Off path. Use physical Off; verify the BedJet stops. If the remote fails, use the unit's normal power-off procedure. Disable charger auto-start and other automated starts; do not issue repeated Start/Restore commands into an unknown operation. Save screenshots/events, then use **Stop tracking** locally if needed—this does not turn the BedJet off. Reconnect only when safe, read fresh status and reconcile. Restore an original slot only after checking the device identity, that the slot is idle and that the correct backup exists; read it back. If reconciliation or restoration cannot be confirmed, leave the unit off and mark FAIL/BLOCKED. Restore phone time, battery settings, permissions and test alarms after the session.
