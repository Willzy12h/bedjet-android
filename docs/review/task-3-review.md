#### Important (Should Fix)

1. **A prepared resume can start after its original wake.** `core/src/main/kotlin/io/github/willzy12h/nocturne/core/night/NightRunner.kt:111–114,149,178–179` and `core/src/main/kotlin/io/github/willzy12h/nocturne/core/night/NightChanges.kt:42–54`. Preparation rejects `now >= wake`, but the RESUME request deadline is only `offer.expiresAt`, and execution's wake-boundary checks cover only RETIME/REAPPLY. Concrete case: stop at 06:55 with a 07:00 wake, prepare resume at 06:59, then acquire the connection/apply at 07:01. The offer lasts until 07:10, so the unchanged identity/generation and deadline checks pass and the programme starts after the agreed wake. The same failure occurs if apply begins at 06:59 but `beforeWrite` finishes at 07:01. **Fix:** bound the resume execution deadline by the earlier of offer expiry and original wake (or enforce an equivalent explicit wake check at each execution eligibility point). Add deterministic regressions for delay before apply and delay inside backup, including equality at wake; assert no slot write/start and truthful terminal state when pending was already published. Existing expiry tests advance to the offer's 15-minute expiry and do not cover this earlier wake boundary (`core/src/test/kotlin/io/github/willzy12h/nocturne/core/night/NightTransactionsTest.kt:107–119`).

2. **Eligibility is not checked after the suspending upload/readback and before starting the slot.** `core/src/main/kotlin/io/github/willzy12h/nocturne/core/night/NightRunner.kt:177–184`. After the pre-store deadline/boundary checks, `controller.store(...)` can consume the remaining lifetime; `controller.startProgram(...)` then runs unconditionally. Concrete case: a re-time passes checks one second before its deadline or confirmed wake-up boundary, then upload/readback takes two seconds. The expired request still starts a new programme and publishes CONFIRMED. The caller's lock cannot stop clock time advancing during I/O. **Fix:** recheck temporal eligibility immediately after store/readback and before start, including the corrected resume wake deadline. If expired, do not start and publish a truthful UNKNOWN outcome because the slot may already have been overwritten; do not claim the old programme survived. Add a focused delayed-store/readback regression that advances the injected clock across the deadline and confirmed wake boundary and asserts that no start command is issued. This is a separate execution window from item 1 and remains broken if only the resume request deadline is clamped.
