## Part A runtime truthfulness and presentation boundary

`night/RuntimeState.kt:endRequested` stores the exact night identity for an attempted ending command. `NightActions.manualChange` writes that intention before sending Off/End or an ending Quick/Remote command and cancels obsolete re-time work. It is an intention, not evidence that a write reached the unit. If confirmation is missing, tracking remains UNKNOWN. `observeStatus`, restart reconciliation and Take back can later finish that matching night as STOPPED from the selected target's Standby report; a head-only report is sufficient for that stopped state. Reconciliation explicitly reconnects for fresh status. Wrong-target reports, another night's marker and UNKNOWN state without an ending intention cannot use this rule to close the current night. `finishLocked` clears the marker, and publishing a different night identity supersedes it. A refused Start/Reapply which retains the same night also retains its intention; the old scheduled end cannot convert an unconfirmed ending command into ENDED. `SendConfirmationTest` covers these distinctions. Physical confirmation, including a later Standby, remains A11/N10, NOT RUN.

`NightActions.remote(endsNight = true)` refuses a missing confirmation predicate before connecting or sending. A Remote fan/temperature adjustment can confirm the individual value while leaving programme tracking UNKNOWN/manual and retaining the old `endsAt`. [ActiveNight.kt](../../core/src/main/kotlin/io/github/willzy12h/nocturne/core/night/ActiveNight.kt) exposes `hasPlannedManualEnd`, true only for `trackingManual && confidence == CONFIRMED`; it is false for that UNKNOWN adjustment state. `ManualTrackingTest` covers the capability.

The merged P5 presentation has its own guards. Tonight uses both the active-night and displayed-status confidence: a manual run reads “Manual run until” only when confirmed, otherwise “Planned end”. `PlanEnd` carries that label through the curve, text alternative and Simple timeline, suppressing wake wording and the wake marker. UNKNOWN manual state still displays its stored `endsAt` as “Planned end”; it is not newly verified by a Remote adjustment. `WidgetPresentation.widgetWake` already returns a pending label for non-CONFIRMED state before its manual branch. The corrected wake-notification path now chooses its end-bearing title only through `hasPlannedManualEnd`; other manual states read “Manual run not confirmed” without an end timestamp. `ManualWakeTitleTest` retains the UNKNOWN/direct-adjustment regressions and confirmed-manual/ordinary-night controls; all four pass in the integration gate. The protected Tonight/widget consumers do not call `hasPlannedManualEnd` directly, but that fact alone is not an absence of confidence guarding. The integration gate passed; physical label checks remain NOT RUN.

`platform/ChargerRun.kt` now records timeout feedback with the interrupted-operation message: the BedJet state is unknown and must be checked. The outcome category remains FAILED for the timed-out attempt; the wording no longer implies a known unchanged device after possible transmission. Charger work stays owned by its job and does not launch `BedJetService`. The charger regression is host evidence; Q05/A14 remain NOT RUN.
