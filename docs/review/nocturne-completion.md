## Part A runtime truthfulness and presentation boundary

**Historical F1 account:** the paragraphs in this section preserve the earlier Part A/F1 source and gate context. Later runtime and haptics claims belong to their immutable source pins above and the current [runtime source pin](docs2-repin.md#5-runtime-policy); these paragraphs are not new verification of those snapshots.

`night/RuntimeState.kt:endRequested` stores the exact night identity for an attempted ending command; F1 adds `endRequestedLabel` and `endRequestedAt` to retain its action label and request time. `NightActions.manualChange` writes that intention before sending Off/End or an ending Quick/Remote command and cancels obsolete re-time work. It is an intention, not evidence that a write reached the unit. If confirmation is missing, tracking remains UNKNOWN. `observeStatus`, restart reconciliation and Take back can later finish that matching night as STOPPED from the selected target's Standby report; a head-only report is sufficient for that stopped state. For a timestamped request, the report must have been received at or after `endRequestedAt`. The late STOPPED event retains `endRequestedLabel`; a legacy identity-only marker uses the neutral “Night stopped.” Reconciliation explicitly reconnects for fresh status. Wrong-target reports, another night's marker and UNKNOWN state without an ending intention cannot use this rule to close the current night. `finishLocked` clears the marker and its label/time, and publishing a different night identity supersedes them. A refused Start/Reapply which retains the same night also retains its intention; the old scheduled end cannot convert an unconfirmed ending command into ENDED. `SendConfirmationTest` covers these distinctions; [F1 implementation evidence](f1-implementation.md) records the follow-up and its verification status. Physical confirmation, including a later Standby, remains A11/N10, NOT RUN.

**Off pending while the BedJet 3 is unreachable:** the same UNKNOWN night stays tracked past its stored `endsAt`. In [NightActions.kt](../../app/src/main/kotlin/io/github/willzy12h/nocturne/night/NightActions.kt), `expireLocked` refuses natural expiry while `endRequested` matches that night, and `reconcile` retains the intention, its label/time and UNKNOWN state when fresh status cannot be obtained. There is no automatic time limit that closes this unresolved ending. It stays tracked until a stopped-state report from the selected BedJet 3 is received at or after the recorded request time, or the user taps **Stop tracking**; a running-state report, a report from another target or a report received before that request cannot confirm Off. Stop tracking closes local tracking without sending a command to the BedJet 3. The existing `SendConfirmationTest.anUnconfirmedOffDoesNotExpireAsAnEndedProgramme` and late-confirmation/restart cases cover the relevant boundaries; the F1 additions are tracked in [F1 implementation evidence](f1-implementation.md).

`NightActions.remote(endsNight = true)` refuses a missing confirmation predicate before connecting or sending. A Remote fan/temperature adjustment can confirm the individual value while leaving programme tracking UNKNOWN/manual and retaining the old `endsAt`. [ActiveNight.kt](../../core/src/main/kotlin/io/github/willzy12h/nocturne/core/night/ActiveNight.kt) exposes `hasPlannedManualEnd`, true only for `trackingManual && confidence == CONFIRMED`; it is false for that UNKNOWN adjustment state. `ManualTrackingTest` covers the capability.

Tonight uses both the active-night and displayed-status confidence: a manual run reads “Manual run until” only when confirmed, otherwise “Planned end”. `PlanEnd` carries that label through the curve, text alternative and Simple timeline, suppressing wake wording and the wake marker. UNKNOWN manual state still displays its stored `endsAt` as “Planned end”; it is not newly verified by a Remote adjustment. `WidgetPresentation.widgetWake` already returns a pending label for non-CONFIRMED state before its manual branch. The corrected wake-notification path now chooses its end-bearing title only through `hasPlannedManualEnd`; other manual states read “Manual run not confirmed” without an end timestamp. `ManualWakeTitleTest` retains the UNKNOWN/direct-adjustment regressions and confirmed-manual/ordinary-night controls; all four pass in the integration gate. The integration gate passed; physical label checks remain NOT RUN.

Charger work stays owned by its job and does not launch `BedJetService`. The charger regression is host evidence; Q05/A14 remain NOT RUN.
